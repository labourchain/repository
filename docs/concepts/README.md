# Concepts

`docs/concepts/` 维护 LabourChain 的长期概念基线。

这些文档用于统一术语、对象关系和解释框架，供需求、Spec、协议、产品设计与实现持续对照。它们不是某个版本的功能需求，也不是工程契约。

Repository 的产品需求唯一事实来源仍然是 [`../requirements.md`](../requirements.md)。当概念基线与需求出现不一致时，应先显式审查两者，而不是由 Spec 或实现自行选择解释。

## 概念文档约定

每篇概念文档尽量围绕少量紧密相关的概念，并使用一致结构：

- **定义**：这个概念是什么；
- **关系**：它与其他 LabourChain 概念如何连接；
- **关键约束**：哪些性质属于概念本身，而不是当前实现偶然形成的行为；
- **投影与区别**：运行时、产品视图或相邻概念如何使用它，但不改变其规范含义。

概念文档不要求一次解释整个 LabourChain。新的稳定概念可以独立增加文档，已有概念发生实质变化时，应同步审查依赖它的 requirements 和 specs。

## 核心概念表

| LabourChain | 中文概念 | 基本含义 |
| --- | --- | --- |
| Worker / Member | 劳动者 / 劳动主体 | 系统中能够产生劳动记录和劳动成果的劳动主体 |
| Record | 劳动记录 / 活劳动 | 对劳动过程的链上事实记录 |
| Asset | 劳动成果 / 死劳动 | 劳动对象化后形成的成果及其链上表示 |
| Repo | 仓库 | 存放劳动成果，并在 contribution 中参与劳动确证 |
| Project | 项目 | 对劳动者、活劳动与死劳动的一种组织形式 |

## 文档

- [`labour.md`](./labour.md) — 劳动者、活劳动、死劳动以及劳动链的数字孪生对象。
- [`repository.md`](./repository.md) — 仓库、Asset contribution、仓库确证、Personal Repo 与运行时投影。
- [`project.md`](./project.md) — Project 作为劳动组织形式，以及它与 Repo 的区别。
- [`access-and-use.md`](./access-and-use.md) — 私人、公开、公共、有痕授权、数据使用和软件资产使用。

## 当前核心基线

> 劳动者是劳动主体；劳动记录是活劳动的数字孪生；劳动成果是活劳动对象化形成的死劳动；仓库存放劳动成果并参与劳动确证；项目组织劳动者、活劳动与死劳动。
