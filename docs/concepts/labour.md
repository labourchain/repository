# 劳动者、活劳动与死劳动

本文说明 LabourChain 中最基础的三个概念：劳动者、劳动记录和劳动成果。

## Worker / Member：劳动者

Worker / Member 指劳动者，也就是劳动主体。在当前模型中，只有劳动者能够产生劳动记录和劳动成果。

劳动者进行劳动时，会形成两类不同性质的链上对象：

```text
劳动者
├── 进行活劳动
│     ↓
│   Record
└── 形成、修改或维护劳动成果
      ↓
    Asset
```

Repo、Project、Runtime、AI、Agent 可以参与劳动的组织、辅助、执行、存储或分析，但当前概念模型不把这些技术系统或组织实体本身视为劳动主体。Record 和 Asset 的生产、修改或维护最终都要能够回到劳动者的劳动过程。

如果以后需要承认新的劳动主体类型，应明确修改概念模型，而不是通过工程类型定义直接扩大 `Worker` 的含义。

## Record：劳动记录与活劳动

Record 是劳动记录，也是活劳动的数字记录。它描述劳动者实际发生的劳动，并作为链上事实存在。

LabourChain 不只记录劳动完成后留下的文件、代码、数据等成果，也把劳动过程本身作为需要记录的对象。一次劳动可以形成新的 Asset，也可以修改或维护已有 Asset；会议、沟通、组织、检查、学习、维护等劳动则可能只有 Record，而没有独立的新 Asset。

```text
劳动
  ↓
Record

劳动
  └── 可能形成 / 修改 / 维护
            ↓
          Asset
```

Record 不依赖某个 Repo 的 `records[]` 字段，也不需要依附 Asset 才能存在。Repo、Board、Flow 等运行时服务可以缓存或索引 Record，但这些缓存只是投影。劳动者的 labour history 由链上与该劳动者相关的 Record 重新构建。

## Asset：劳动成果与死劳动

Asset 是劳动成果，也就是已经对象化的劳动。代码、文档、数据、模型、设计、构建产物，以及现实劳动成果的数字表示，都可以成为 Asset。

Record 和 Asset 都有链上的规范表示，但记录的是不同对象：

```text
Record = 活劳动
Asset  = 对象化后的劳动成果 / 死劳动
```

Asset 不是任意可存储数据的同义词。Runtime cache、临时 API response、LLM context 等内容不会因为能够被保存就自动成为 Asset。一个 Asset 可以在后续劳动中继续被使用、修改或维护，并与新的 Record 建立关系。

## 活劳动的数字孪生

现有系统已经普遍能够保存劳动成果。LabourChain 同样记录这些成果，但它还试图把活劳动本身记录为链上事实，使劳动者、劳动过程、劳动成果以及相关的组织和确证关系能够被重新构建。

因此，LabourChain 同时记录活劳动和死劳动，其中更有区别性的部分是对活劳动建立数字孪生。
