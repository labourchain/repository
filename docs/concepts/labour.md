# 劳动者、活劳动与死劳动

本文定义 LabourChain 最基础的劳动对象：劳动者、劳动记录和劳动成果。

## 劳动者 / Worker / Member

### 定义

**Worker / Member = 劳动者 = 劳动主体。**

劳动者是 LabourChain 中能够产生劳动记录、产生劳动成果的劳动主体。

### 关系

劳动者通过劳动形成两类不同性质的链上对象：

```text
劳动者
├── 进行活劳动
│     ↓
│   Record
└── 形成、修改或维护劳动成果
      ↓
    Asset
```

Repo、Project、Runtime、AI、Agent 等可以参与劳动过程的组织、辅助、执行、存储和分析，但在当前概念模型中不替代劳动者成为劳动主体。

### 关键约束

- Record 的劳动主体必须能够回到劳动者；
- Asset 的生产、修改或维护也必须能够回到劳动者的劳动过程；
- 当前模型不把技术系统或组织实体直接建模为 Worker。

如果未来需要承认新的劳动主体类型，应作为概念模型的显式修订，而不是由工程类型定义暗中扩大 `Worker` 的含义。

## Record / 劳动记录 / 活劳动

### 定义

**Record = 劳动记录 = 活劳动的数字记录。**

Record 描述劳动者实际发生的劳动，是链上的事实记录。

LabourChain 的一个核心目标，是把活劳动本身提升为第一等数字事实，而不仅仅记录劳动完成后留下的文件、代码、数据或其他成果。

### 关系

Record 可以描述劳动者：

- 形成新的 Asset；
- 修改或维护既有 Asset；
- 进行没有独立 Asset 产出的劳动，例如会议、沟通、组织、检查、学习或维护。

因此：

```text
劳动
  ↓
Record

劳动
  └── 可能形成 / 修改 / 维护
            ↓
          Asset
```

### 关键约束

- Record 不依附某个 Repo 的 `records[]` 容器才能存在；
- Record 不必依附 Asset 才能存在；
- Record 是规范链上事实，Repo、Board、Flow 等运行时可以缓存或索引它，但缓存不是 Record 的规范存储位置；
- 劳动者的 labour history 可以由与该劳动者相关的 Record 重新构建。

## Asset / 劳动成果 / 死劳动

### 定义

**Asset = 劳动成果 = 已对象化的劳动 = 死劳动。**

Asset 表示劳动已经对象化之后形成、修改或维护的成果。代码、文档、数据、模型、设计、构建产物，以及现实劳动成果的数字表示，都可以成为 Asset。

Asset 与 Record 一样具有链上的规范表示，但二者表达不同性质的事实：

```text
Record = 活劳动
Asset  = 对象化后的劳动成果 / 死劳动
```

### 关键约束

- Asset 不是“任意可存储数据”的同义词；它需要进入 LabourChain 的劳动成果关系；
- Runtime cache、临时 API response、LLM context 等不会因为技术上可以存储就自动成为 Asset；
- 一个 Asset 可以在后续劳动中被继续使用、修改、维护并与新的 Record 发生关系。

## 劳动链的数字孪生对象

大量现有系统已经能够记录劳动成果，也就是死劳动的数字对象。LabourChain 同样记录这些成果，但更核心的差异在于：

> 把活劳动本身作为链上事实记录下来，并使劳动者、劳动过程、劳动成果及其组织和确证关系可以被重新构建。

因此，LabourChain 同时记录活劳动与死劳动，而其更具区别性的目标是建立**活劳动的数字孪生**。
